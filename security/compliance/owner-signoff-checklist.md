## C. 11-12 到期不齐的后果（提前知悉，避免意外）

1. 三件任何一件未齐 → 台账记「**未闭环**」（禁写「已获授权/已解决/合规」），**residual 保留**并显著登记（register.md SEC-011）。
2. C 端维持 `internal_eval` + 403 `EntitlementRestricted`（红线③），**不因任何口头承诺翻档**。
3. 11-12 发布**数据半不签**（H4 veto 范围）；C 端商用上线继续阻塞（P0）。
4. 若 A1/a/b 的答案是「只覆盖官方端点」→ 换源是**授权基础变更**（不是配置切换）：切 `api.tushare.pro` + 重拉全量 + 条款重新对表，另行排期。

## E. 常见误区（会被退回的说法）

- 「tushare 那边口头说可以商用」→ 无书面实体 = 无权利基础（L127：口头声明被拦截；不得写「owner 已获授权」当结论）。
- 「tuaremax 卖我服务就是授权我」→ reseller 转售链条**不构成** tushare 再许可授权（L118）；这正是 residual 本身。
- 「内网/自己人看不收费就行」→ 内网≠免授权（L100）；「熟人小范围不收费」= 再分发（L100 ②），仍需三要件。
- 「条款我大概记得」→ 只认全文 + 版本号 + 来源 URL 的 sha256 快照，转述不算（三件②）。
