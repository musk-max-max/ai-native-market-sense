# ADR-004：对外契约的来源词表（平台语义，不含厂商标识）

- 状态：Accepted（Lead 2026-11-04 指令；P0 尚无外部消费者，按 pre-freeze 处理，H2 会签后补齐）
- 决策者：Lead + A0（契约 owner）
- 关联：decisions #1（OpenAPI 单一真源）、#4（canonical/source 元数据）、F1（上游数据授权未落地）、ADR-001 D4/D5、ADR-002 D2a/D2b

## 背景

A7 在写前端来源映射时发现一个真实冲突：契约 `SourceRef.source` 当时是自由字符串（`pattern` + `examples: [tushare]`），前端要做展示映射就必须在 `web/h5` 里写厂商标识字面量，撞上 DA-3/L1 的「禁止源格式/厂商标识进入展示与数据层」红线。更严重的是，`examples: [tushare]` 会被 openapi-typescript 抄进生成客户端的注释，厂商名已经出现在 `packages/api-client/src/generated/*.ts` 里——前端照着生成产物写 mock 就会把厂商名带进仓库。

这不是前端问题，是契约把「内部供数实现」泄漏成了「对外承诺」。

## 决策

1. **`SourceRef.source` 改为封闭枚举（平台词表）**，只描述平台对数据的承诺，不描述数据从哪家买：

   | 取值 | 含义 | 使用场景 |
   |---|---|---|
   | `platform_realtime` | 盘中实时 | P1 预留，P0 不启用 |
   | `platform_delayed` | 延时行情 | 延时展示 |
   | `platform_eod` | 收盘后官方快照 | P0 行情主口径 |
   | `platform_snapshot` | 最近一次成功快照 | 降级展示（AC-1b） |
   | `platform_degraded` | 降级/过期状态 | 数据来自缓存且已标 stale |
   | `platform_watchlist` | 自选列表响应 | 平台自有数据 |
   | `platform_fundamental` | 财报响应 | 平台整理口径 |

   前端可写 `Record<SourceValue, string>`，漏 key 在 `tsc` 阶段失败；`SourceValue` 由 `@market-sense/api-client` 从生成产物导出。

2. **对外契约与生成产物中不得出现供数厂商标识**：包括 schema 的 `description`、`examples`、字段说明，以及 `packages/api-client/src/generated/**`。F1 的授权背景、换源策略属于 ADR/内部文档，不属于对外契约。
3. **保留内部溯源字段 `SourceRef.source_id`（optional）**：仅审计/排障用，不参与 C 端展示，不在契约里枚举取值。前端不得据此渲染来源文案。
4. **C01 厂商标识门禁落成提交脚本**：`infra/ci/check-source-vocabulary.mjs`（见 ADR-002 D2b），CI 的 contracts job 挂载；扫描面显式包含 `contracts/**/*.yaml`（含描述文本）与 `packages/api-client/src/generated/**/*.ts`。门禁不是一次性 grep。

## 理由

- **合规负债**：F1（上游商用/再分发授权）未落地，对外公开背书一个尚无授权关系的供数方，是把合规风险写进产品文案。用平台词表，C 端只承诺「平台行情快照」及其时效。
- **架构债**：换源是这套数据端口设计专门保留的能力（ADR-002）。若前端/契约绑定厂商标识，换源当天要改契约、生成客户端、前端映射和测试；平台词表把换源收敛在适配层。
- **可测试性**：封闭枚举让「漏映射」变成编译错误，而不是线上显示空白；也避免自由字符串随时间漂移出 `tushare`、`Tushare`、`ts` 等多种变体。

## 后果

- A1/A3 产出响应时只能填平台词表；厂商信息留在适配层内部（C01 豁免边界，ADR-002 D2a）。
- A11 契约测试断言：`source` 枚举有限、成员全部匹配 `^platform_[a-z_]+$`、不得含厂商标识；provider 录播样本需同步为新词表。
- A7 前端映射测试断言每个枚举成员都有展示文案（覆盖测试由 A7 写，A0 保证枚举有限且显式）。
- 新增/删除来源档位属于契约变更：按 ADR-001 D5 属破坏性变更，须走 D6 流程（PR diff + H2 签字）；因此词表在 P0 要尽量一次定全。

## 被否选项及原因

| 选项 | 否决原因 |
|---|---|
| 保持自由字符串 + 更新 examples | 厂商名仍会进生成产物与前端 mock；且自由字符串无法让前端穷尽映射 |
| 枚举里保留厂商名（`tushare`、`wind`…） | 把供应商变成对外契约的一部分，换源即破坏性变更，同时构成合规背书 |
| 「禁止出现 tushare 五个字母」的字符串匹配 | 会误伤内部文档/ADR 的正常讨论，团队会用 `t-u-s-h-a-r-e` 绕过；应划清扫描面（对外契约+生成产物），而不是写更严的匹配 |
| 把来源映射放进 API 返回的展示文案 | 展示文案是 H5 职责（A7/A10），契约只给稳定枚举；否则每次文案调整都要改契约 |
| 删除 `source` 字段，只留 `as_of` | 前端无法区分实时/延时/降级，C2 的 stale 展示与 AC-1b 依赖来源语义 |

## 可逆性

- **高**：词表是纯枚举，增删档位只需改契约 + 生成客户端 + 前端映射表；无数据迁移。
- 若未来确需对外披露供数方（见下），在 ADR-004 追加「唯一 label-map 文件」窄豁免并人类签字，不放宽全局扫描面。

## H3/H4 判定记录（2026-11-04）

**H3 书面结论（原文要点，可引用）**：分两层，不能合并成一句。

1. 监管「数据披露义务」：**可满足**。C 端只出现「平台行情快照 / 平台财报」+ 更新时点 + 口径说明 + 风险提示，不点名第三方供数方，监管上通常不构成披露缺陷——监管要的是来源合法、真实、准确、及时的实质要件，不是向 C 端用户公示商业供应商名称。
2. 授权「披露/署名义务」：**不满足**。F1 商用与再分发授权未落地时，缺的是权利基础，不是标注形式；点不点名都不改变「当前无再分发权」这一事实。label-map 窄豁免 + 人类签字只能承接过渡期风险，**不产生授权**，不得写成「已满足授权披露义务」。
3. 合并结论：**不满足**（缺口在授权侧，不在文案侧）。

**不触发 H3 的 C 端 veto 的部分**：行情快照、财报是客观数据展示，不构成 40 号文四项下的「具体品种投资分析意见/选择建议/买卖时机建议」。红线：前端一旦由快照派生涨跌幅解读、评级、「值得关注/可关注」、买卖时点提示，立即进入禁区，须走 H3 表述预审。

**label-map 窄豁免（仅过渡措施，四个硬条件缺一不可）**：
a. 绑定授权取得 deadline，到期**自动 fail-closed**（配置层硬失效、默认不渲染），不靠人记；
b. 豁免范围仅限集中 label-map 单文件，**不放宽**对外契约与生成产物门禁；
c. 签字仅作风险承接，文本须写明「不构成授权、不替代授权」，签字人为法务会签后指定人；
d. 授权取得前，C 端对该源数据一律降级不展示，不得带病展示。

**分工与剩余输入**：对外表述与披露口径归 H3；授权链条、合同条款归 H4。H3 明确「是否需要点名」的最终定性取决于上游合同署名条款 + 《金融信息服务管理规定》下来源标示要求的具体解释，需法务就合同条款出书面意见（H3 给口径，不给定性）。联合结论需三件齐备：H4 授权状态确认、律师署名条款意见、上述 fail-closed 时间盒落地。

**对契约的影响**：本 ADR 的「契约只出现平台词表」保持不变；若最终定性要求点名，仅在 C 端 label-map 单文件按上述窄豁免处理，契约与生成产物仍不出现厂商标识。当前无任何契约动作待定。

### H4 书面判定（2026-11-04，原文要点；与 H3 不冲突）

**结论：不满足（授权披露维度）。** 且不是文案能修好的不满足——满足判定的门槛是条款文本，不是页面措辞。H3 侧（监管披露可满足 / 授权披露不满足）与 H4 不冲突，联合结论按 **不满足** 记。

依据：
1. **授权现状：无书面许可。** 只有积分套餐购买关系，没有任何文件确认 to-C 商用、再分发、展示权。付费≠授权；未取得 = 按不允许处理。
2. **再分发/展示范围：未确认。** C 端向终端用户展示上游数据，至少是 display、可能构成 redistribute；个人/研究用途套餐默认不覆盖，具体范围没有文本。
3. **署名/来源标示条款：未取得。** 上游服务条款书面版本不在手，是否要求署名、是否禁止以平台名义转述，均为未知，按「可能要求」处理（最坏情形）。
4. **平台词表解决的不是这件事。** ADR-004 的架构理由与「不做无授权关系方背书」成立，但契约清干净厂商标识 ≠ 取得授权。反向风险：条款要求署名而页面只说「平台行情快照」= 违约；条款禁止以平台名义表述来源 = 来源误导，比未署名更重。

F1 书面文本到手后的三档判定：
- **A** 含 to-C 商用 + 再分发，且不要求署名/允许平台口径表述 → **满足**，ADR-004 定稿，H4 签字。
- **B** 含商用但要求署名 → **不满足，必须点名**。采 label-map 方案：唯一集中文件、仅 C 端展示文案层、只做显示名映射；不得回灌契约/生成产物/数仓/接口枚举；每次改动记版本 + 依据条款；H3+H4 签字登记；扫描面与 C01 门禁不放宽。方向上预认，但它是**风险承接**，不等于「已满足」。
- **C** 未覆盖 to-C 或禁止再分发 → 点名也不够，C 端不得展示该源数据。

**授权未落地期间是否允许商用展示：不允许。** 机制已存在：`entitlement.tier` 停在 `internal_eval`、`is_entitled=false`、行情/财务走 403 `ENTITLEMENT_RESTRICTED`、C 端不渲染数值。平台词表不改这条。tier 翻 `c_end_display` 的前置是 **F1 书面授权 + H4 签字，缺一不可**。

**时间盒（与 H3 一致）**：F1 书面回复到期 **2026-11-12**（7 个工作日）；到期无书面授权自动按情形 C 处理，C 端不渲染，不再开会补票。kill-switch 落在数据侧 entitlement 配置，不由前端自觉。

**明确不接受**：前端承担该决定；以「契约已清厂商名」作为披露满足依据；把 label-map 窄豁免说成「已满足」。

### H4 补充：基础信息展示口径（2026-11-04 判定，2026-11-12 前正式落文）

P0 允许展示的基础信息白名单**定稿 7 类**（H4 m00817）：`instrument_id`、`name`、`exchange`、`board`、`security_type`、`list_status`、`listed_at`；按「单一事实、不构成作品」处理。前提是与上游供数方解耦——这批字段由 A1 从交易所公开披露/自建导入维护，不依赖 F1 授权。`security_type` 属交易所规则下的分类事实（H4 口径原漏列，补入）。`lot_size` **不在白名单**（「最小申报数量 ≠ 交易单位倍数」会误导），按 D5 从契约删除。**已执行（2026-11-04）**：A11 确认 A3/前端无消费方，H2 书面签字，`market` 0.2.0→0.3.0，api-client 重生成无该字段；A11 负责 waivers.yaml 台账（approved_by 指向 `agents/decisions.md` L6-附 2026-11-04 行、expires_at 2026-12-15），oasdiff 盲区由 `contracts/oasdiff-severity.txt` 把该类变更升为 `err` 覆盖（H2 L45：不自写 policy-breaking differ，统一 `--severity-levels`）。

三个约束：
1. 白名单外不放（含价格、成交量额、涨跌幅、市值、PE/PB、财务数值）——这些走受授权约束接口与 403/entitlement 机制。
2. **概念板块归属不在白名单**（第三方整理汇编，F1 未落地前不可展示，与 10000 积分档绑定）。
3. 只做逐条/单页展示，不做整表导出/下载/批量复制接口；全市场列表接口 P0 不开，限流规则落 `services/api` preHandler 通用配置。

契约处理：`contracts/market/openapi.yaml` 的 `getInstrument` 描述已加一句「基础信息字段集与来源见 H4 基础信息白名单口径（2026-11-12）」，语义不变（仍不整体 403），只是避免契约替数据侧背书展示范围；本次为 description-only，无 schema/兼容性变化。

### 11-12 放行验收（H4 2026-11-04 状态更新；与判定分开写）

H4/H3 联合判定已在 H3 侧闭合；11-12 只验收以下三项（缺一按未交付）：

1. 过期配置拒答的测试证明（配置存在不算）。
2. `(c)` 白名单外字段默认拒绝的测试。
3. 三类事件（到期自动翻转 / 三档切换 / 条款复核）抽样可回指条款原文。

口径说明（Lead m00730 / H4）：A/B/C 三档的 `(c)` 字面含义就是「白名单外字段默认拒绝」，**不是**三档分级；同时不要把「判定已闭合」误读为「授权已到位」。

接口侧限制（H4 m00789/m00817 定稿）：**P0 不开全市场基础信息列表接口**（H5 建议、H4 同意；比做分页限流更省）。原「待 H2/A0 落全市场列表接口限制」要求已撤回，不留待办；限流规则落 `services/api` 的 preHandler 通用配置（≤50 条/页、offset 上限、60 次/min/IP 等，具体数值以 H5 口径为准），未来接口上线即继承；契约不新增全市场列表 API、不做全集镜像。

`compliance_rule_version`：只在事件与埋点侧记录（同时维护 `text_version` 与 `rule_version` 的 append-only 映射），**不进响应体**，不作为契约 body 字段；若未来要进契约，属 D6 变更，由 A0 + H2 走。

正向正例待补：H4 已给出 7 类字段清单，A11 补白名单内正例（含 `security_type`，并断言 `lot_size` 不在返回），当前已有白名单外字段默认拒绝的反向断言。
