# 质量分红灯（数据质量门禁未过）

- runbook_id: RB-QUAL-001
- owner: A13（执行）· A2（warehouse）· A11（测试/数据质量）· H4（数据负责人）
- 最后演练: 待 S1 首次演练（date TBD）
- 关联告警: `QualityGateRed`、`QualityGateScoreDrop`
- 关联 SLO: asof_freshness、availability_offhours

## 症状

1. `QualityGateRed`：`quality_gate_status{gate=~".+"} == 0` 持续 10 分钟（任一质量门禁红）。
2. `QualityGateScoreDrop`：当日质量分比 7 日中位数下降 > 20%（即使未红也进入本流程）。
3. 典型红项：价格跳变超涨跌停约束、复权因子异常、停牌股出现成交、榜单未中性化、字段空值率超阈、东财/tushare 口径冲突。
4. 发布前人工发现 gold 层校验不过，或 `data/golden/` 对照失败。

## 影响

- 错误数据会被榜单/个股页直接展示 → 用户信任受损，比短暂不可用更严重。
- 若已进入 `published` 配置或已生成快照，错误会扩散到缓存与客户端；修复成本随时间指数上升。
- 触发 A 股合规展示风险（涨跌幅/停牌标识错误）→ 需 H5 知会合规。

## 判断（≤10 分钟）

1. 看门禁明细：`quality_gate_status` 按 gate 标签展开，定位红的是哪一类校验。
2. 对比 ODS/DWD/Gold 三层同日分区行数与空值率，确认是「源数据缺」还是「计算错」。
3. 查上游 tushare 当日接口返回是否异常（停牌/除权日/代码变更/退市）。
4. 查当日是否有发布或配置变更（`market_sense_build_info`、配置发布记录）；发布后 30 分钟内变红优先怀疑发布。
5. 判定影响面：是否已发布（`published` 版本号）、是否已被页面读取、影响哪些接口/榜单。

## 止血

1. 立即冻结发布：保持 `draft` 不发布，阻断数据继续进入 `published`；页面继续读上一个已发布版本。
2. 若错误数据已发布：回滚配置到上一 `published` 版本（走配置发布流程，需 H5 批准）；页面显示「数据校验中」横幅。
3. 对已污染分区做标记（不直接删），由 A2 重跑对应 DWD/金层分区；重跑前先保留现场快照用于复盘。
4. 若为上游源数据错误：暂停该域刷新（feature flag），升级 H4 与 tushare 侧确认；不得自行篡改源数据。
5. 全部恢复判据：质量分回到 7 日中位数 ±10%，且门禁全绿，才能重新放行发布。

禁止：为了过门禁而放宽阈值（改阈值必须走 PR + H4 评审 + 记录原因）、手工 UPDATE gold 表、绕过 pipeline 直接改线上快照。

## 升级

- 门禁红超过 30 分钟 → 升级 H4 + A2 + A11。
- 已对外展示错误数据 → 立即 H5（是否公告/修正说明）+ 合规跟踪人（F2/F3）。
- 涉及 tushare 授权/口径争议 → H4 决策，A13 不自行处理。

## 复盘

- 24 小时内：确认根因在源、计算还是发布；统计受影响分区与用户可见时长。
- 48 小时内：把该失败模式加入 `data/golden/` 对照与 `tests/data/` 回归；修订阈值需附数据依据。
- 若因阈值过宽导致漏检，同步调紧并在本 runbook 记录变更。

## 质量门禁清单（发布前必须全绿）

| 门禁            | 含义               | 红时动作              |
| --------------- | ------------------ | --------------------- |
| `price_bounds`  | 价格/涨跌幅不越界  | 暂停发布，查停牌/除权 |
| `adjust_factor` | 复权因子连续可解释 | 查除权日与源数据      |
| `null_rate`     | 关键字段空值率超阈 | 查上游缺失            |
| `neutrality`    | 榜单中性化通过     | 查榜单计算与权重      |
| `golden_diff`   | 与 golden 对照通过 | 定位差异分区          |
