## 1. 主题清单定稿（P1a = 3 个主题）

零售 C 端用户最关心的前三个问题，按「先看公司质量 → 再看贵不贵 → 最后看钱怎么流」的自然决策顺序排列。每个主题回答一个散户的口语化问题，并组合多个数据集形成层次。

| 主题 Key | 主题名 | 回答的散户问题 | 喂养数据集 | 冷热定位 |
|---|---|---|---|---|
| **T1 fin-health** | 财务健康 | 「这家公司赚钱能力如何？现金健康吗？会不会暴雷？」 | fina_indicator + income | 以冷为主（财报季度更新），热区仅展示最新一期 |
| **T2 valuation-price** | 估值与价格 | 「现在这个价贵不贵？最近走势怎么样？」 | daily_basic + daily | 以热为主（日频/近 30 日），冷区做历史区间对比 |
| **T3 money-sentiment** | 资金与情绪 | 「大钱在进还是在出？市场情绪偏哪边？」 | moneyflow + top_list + margin + stk_limit（市场级） | 以热为主（近 30 日资金/龙虎/两融），涨跌停为市场级热数据 |

**定稿结论（回应 PM §7-Q1）**：
- 这 3 个主题**已覆盖**零售用户最关心的前 3 个问题（质量 / 价格 / 资金情绪），建议 **P1a 锁定这 3 个**，不要扩。
- 「股东/筹码」（hk_hold 北向、十大流通股东）**不建议 P1a 独立成主题**：数据频率低（季度/旬）且对短线散户决策权重次于资金面，建议 **P1b 再评估**是否并入 T3 作「聪明钱」子模块。
- 「技术面」（均线/MACD 等）**不建议进 P1a**：属高计算、强主观、易滑向荐股暗示，与 HARD-002 红线冲突风险高，P1a 排除。

## 2. 每主题字段选取（主 / 次 / 三级 + 冷热归属）

层级定义：
- **P（Primary，一眼区）**：首屏 3 个以内大数字，散户扫一眼就形成判断。
- **S（Secondary，核心明细）**：折叠/次屏，支撑 P 的解释，5–8 个。
- **T（Tertiary，下钻明细）**：点开才看，专业补充，可懒加载。

冷热归属：**热 = 近 30 日（≤30d，走实时/近实时查询）**；**冷 = >30d（走 cold query，允许分钟级延迟）**。财务类字段可能「最新一期走热、历史序列走冷」，行情类整体走热。

### T1 财务健康（fina_indicator + income）

| 层级 | 字段（127 目录语义名 / income 列名待对齐 schema.sql） | 金融理由 | 冷/热 |
|---|---|---|---|
| **P1** | ROE（净资产收益率 weight_roe / roe） | 巴菲特式核心质量指标，单数字代表赚钱效率，散户认知度最高 | 最新一期热 + 近 8 季冷序列 |
| **P2** | 营收同比（income: total_revenue 同比 / fina_indicator 的 or_yoy） | 「长大没长大」直观信号，正负一目了然 | 热最新 + 冷 8 季 |
| **P3** | 资产负债率（fina_indicator: debt_to_assets） | 暴雷/偿债风险唯一关键守门指标，>70% 需警惕 | 热最新 + 冷 8 季 |
| S1 | 归母净利润同比（income: n_income 同比 / np_yoy） | 利润端是否同步营收，识别「增收不增利」 | 热最新 + 冷 8 季 |
| S2 | 毛利率（gross_margin / grossprofit_margin） | 商业模式护城河粗判 | 热最新 + 冷 8 季 |
| S3 | 净利率（net_margin） | 盈利质量 | 热最新 + 冷 8 季 |
| S4 | 经营现金流/营收（目录 cash_to_revenue 或现量表代理） | 「纸面利润 vs 真现金」，识别财务粉饰 | 热最新 + 冷 8 季 |
| S5 | 营收绝对值（income: total_revenue） | 体量感，避免只看比率被小基数误导 | 冷（历史）+ 热最新 |
| T1 | 扣非净利润同比 | 剔除一次性损益的真实盈利 | 冷 |
| T2 | 资产/负债绝对值 | 大额明细，专业用户下钻 | 冷 |
| T3 | 每股收益 EPS（basic_eps） | 与估值主题 T2 衔接 | 热最新 + 冷 |

**income 列名对齐提示（回应 PM §7-Q2）**：PM 草稿用 total_revenue / n_income 为占位，**需以 warehouse/dwd/schema.sql 实际列名为准**（东方财富口径常见 revenue / n_revenue / n_income_attr_p 等）。金融专家不写代码、不锁列名，字段语义以上表语义名为权威。

### T2 估值与价格（daily_basic + daily）

| 层级 | 字段 | 金融理由 | 冷/热 |
|---|---|---|---|
| **P1** | 市盈率 PE-TTM（daily_basic: pe_ttm） | 估值第一指标，散户最熟 | 热（每日更新，近端热） |
| **P2** | 最新收盘价 + 近 30 日涨跌幅（daily: close + 派生） | 「现在多少钱、最近涨没涨」 | 热 |
| **P3** | 市净率 PB（daily_basic: pb） | 补 PE 失真场景（周期/亏损股） | 热 |
| S1 | PE 历史分位（近 1 年/近 3 年，daily_basic 冷序列派生） | 「贵不贵」要与自身历史比，不能只看绝对值 | 冷（历史序列） |
| S2 | 总市值（daily_basic: total_mv） | 体量/盘子大小 | 热 |
| S3 | 换手率（daily 派生 / daily_basic） | 活跃度/关注热度 | 热 |
| S4 | 近 1 年最高/最低价（daily 冷序列派生） | 区间位置感 | 冷 |
| T1 | PE-TTM 近 1 年走势序列 | 下钻看估值变化 | 冷 |
| T2 | 股息率（daily_basic: dv_ttm，如目录含） | 价值股视角 | 热最新 |
| T3 | 流通市值（circ_mv） | 与总市值对比看解禁/流通结构 | 热 |

**T2 独立性定稿（回应 PM §7-Q3）**：**T2 独立成主题，不并入 T1**。理由：财务（季频、冷）与估值价格（日频、热）节奏和数据源差异大，合并会让单屏冷热混杂、刷新策略冲突；且「值不值」= 质量(T1) × 价格(T2) 两步判断，散户心智上本就是两次。T1/T2 通过 T1→T2 的衔接字段（EPS、PE）软关联即可，不必物理合并。

### T3 资金与情绪（moneyflow + top_list + margin + stk_limit）

| 层级 | 字段 | 金融理由 | 冷/热 |
|---|---|---|---|
| **P1** | 主力净流入（moneyflow: 主力净流入额/率，近 5 日/近 20 日） | 「大钱方向」最直接单一信号 | 热 |
| **P2** | 融资余额及变化（margin: rzye 近期变化） | 杠杆资金情绪，散户可感知热度代理 | 热 |
| **P3** | 市场情绪温度（stk_limit 市场级：当日涨停家数 / 跌停家数） | 个股所处大环境冷热，「今天行情好不好」 | 热（市场级） |
| S1 | 龙虎榜上榜记录（top_list，近 30 日该股上榜次数/方向） | 短线资金博弈信号 | 热（近 30d）/ 冷（更早） |
| S2 | 大单/超大单净流入明细（moneyflow 分档） | 主力行为结构化拆解 | 热 |
| S3 | 融券余额（margin: rqye） | 空头/对冲视角，A 股融券体量小作补充 | 热 |
| T1 | 两融余额近 30 日序列 | 趋势下钻 | 热+冷 |
| T2 | 北向持股 hk_hold | 「聪明钱」，建议 P1b 再上，P1a 暂缓 | 旬频，冷为主 |
| T3 | 行业资金流向对比 | 个股资金在板块中相对位置 | 热 |

**T3 情绪框架定稿（回应 PM §7-Q4）**：
- **涨停/跌停家数（市场级）已足够**作为 P3 情绪温度基础，**建议补充「涨跌家数比」（涨:跌 家数）与「连板高度」（最高连板数）**——这三个市场级计数共同构成「情绪温度计」，均属 stk_limit 派生的市场汇总，符合 H3 m02407。
- **北向持股 hk_hold**：有「聪明钱」叙事价值，但旬频更新 + 境外口径波动 + 数据可得性不稳，建议 **P1a 不纳入，放 P1b 评估**；P1a 用「主力资金 + 两融 + 市场涨跌停温度」三件套已自洽。

## 3. 分析层级（首屏 → 下钻 → 对比）

### 3.1 首屏（P 层，一眼区）
用户进入某主题，先看到**不超过 3 个大数字 + 一句人话结论**。例：T1 一眼区 = ROE / 营收同比 / 资产负债率三数字横向并列，下方一行结论句。

### 3.2 下钻路径（P → S → T）
- P 层点任意大数字 → 展开 S 层明细卡片（同主题内）。
- S 层点具体指标 → 进入 T 层序列/明细（懒加载，容忍冷查询分钟级延迟）。
- 下钻**不跨主题跳转**，保持单主题内闭环；跨主题用顶部主题 Tab 切换（T1↔T2↔T3）。
- T1 下钻：单指标近 **8 个季度**序列（季频财报自然周期）；T2 下钻：近 **1 年**日频；T3 下钻：近 **30 日**资金序列。

**下钻深度定稿（回应 PM §7-Q6）**：T1 近 8 季、T2 近 1 年、T3 近 30 日**对零售用户已足够**，不建议更长——更长历史（3–5 年财务、3 年估值分位）属专业深度，P1a 用「近 1 年/近 3 年估值分位」这一个冷派生指标即可覆盖长周期需求，无需在 T 层铺长序列，避免冷查询成本和认知过载。

### 3.3 对比维度（在 S/T 层提供）
- **同比 YoY（period-over-period）**：财务类核心对比（营收同比、利润同比），T1 必备。
- **环比 QoQ**：T1 利润端补充（单季环比识别拐点），作 T 层。
- **自身历史对比**：估值分位（T2）、指标近 N 季趋势（T1）、资金近 N 日趋势（T3）——「和过去的自己比」。
- **绝对值 vs 比率 双轨**：关键指标同时给绝对值（营收/市值/净流入额）和比率（同比%/ROE%/换手%），避免小/大基数误导。首屏优先比率（易跨公司比较），明细补绝对值。
- **同业/板块对比（Peer）**：P1a **仅作 T3 行业资金流向对比**（个股资金在板块中位置）；财务/估值同业对比（如「ROE 在行业中位数上/下」）需行业聚合数据，**建议 P1b 再上**，P1a 不做同业分位，避免引入行业分类口径和额外聚合查询。

## 4. 红线（金融专家必须守的边界）

### 4.1 HARD-002：不给投资建议措辞
P 层「一句人话结论」**只做事实描述与历史呈现，不做评级/目标价/买卖信号/未来预测**。散户要「说人话」，但人话 ≠ 建议。措辞边界：

**可接受（事实/历史/结构性描述）**：
- ✅ 近 8 季 ROE 中位数 12%，最新一期 15%，处于近两年偏高水平。
- ✅ 最新一期营收同比 +20%，连续 3 季为正。
- ✅ 资产负债率 65%，近 4 季稳定。
- ✅ 当前 PE-TTM 位于近 1 年第 30 百分位（偏低区间）。
- ✅ 近 5 日主力资金净流入，融资余额上升。
- ✅ 今日全市场涨停 45 家、跌停 8 家，涨跌比偏多。（市场级计数）

**不可接受（评级/建议/预测/信号）**：
- ❌ 值得买入 / 建议增持 / 目标价 XX 元 / 评级 A。（评级与建议）
- ❌ 预计下季营收增长 / 看涨 / 看跌 / 即将突破。（预测）
- ❌ ROE 高说明公司优秀，可重点配置。（把指标解读成投资结论）
- ❌ 主力进场，跟庄买入。（资金信号 → 交易指令）
- ❌ 情绪冰点，是抄底好时机。（情绪 → 择时建议）
- ❌ 估值偏低，安全边际高。（估值 → 价值判断/买入暗示）

判定口径：结论句只能是「**历史/当期数据是什么**」（描述），不能是「**所以该怎么办**」（处方向）。凡含「建议/值得/预计/将/可买/可卖/目标/评级/低吸/抄底/止盈/止损」等词一律拒绝。

### 4.2 红线①：AKshare realtime_quote 不进 C 端
AKshare realtime_quote（实时行情）**永不进入 C 端**（红线#1）。T2 价格/涨跌幅走 Tushare daily（日频），**不提供盘中实时价**。C 端 T2 首屏的「最新价」语义为**最近收盘价**，UI 需明确标注「收盘价/日频」，不得呈现为实时刷新，避免用户误以为盘中实时。

### 4.3 涨跌停梯队：仅市场级汇总（H3 m02407）
涨跌停梯队（stk_limit / limit ladder）在 C 端**仅允许市场级聚合计数**（涨停家数、跌停家数、涨跌比、连板高度等汇总数字），**不得下钻到「某只个股在梯队的第几板 / 个股涨停名单行」**。per-instrument 梯队行属红线，C 端 T3 的 P3 情绪温度只用汇总计数。

### 4.4 冷热边界纪律
- 热（≤30d）走实时/近实时；冷（>30d）走 cold query，UI 需容忍分钟级延迟并降级（详见 PM 文档 Q4 频控降级三态）。
- 财务类「最新一期」若落在近 30 日内走热，历史序列走冷；估值/行情/资金类整体偏热。
- 同一主题内冷热混排时，首屏优先热字段（体感快），冷字段下沉到 S/T 层并接受延迟。
