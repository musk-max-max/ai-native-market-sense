# market-sense-h5 · Agent 团队编制与运行手册

> 定义源：`agents/roster.yaml`（26 条：20 agent + 6 人类席位）
> 版本：0.1.0 ｜ 2026-11-03
> 原则：**人是责任主体，agent 是产能单元。** agent 不能签字，只能被签字。

---

## 1. 一图看懂编制

| 层 | 席位 | 常驻/任务型 | 说明 |
|---|---|---|---|
| 决策层（人） | H1 PM/PO · H2 架构 · H3 合规 · H4 数据 · H5 安全运维 · H6 业务 | — | 6 人，拥有签字权与否决权 |
| 架构层 | A0 契约 owner | 常驻 | 唯一真源守门人，有跨模块裁决权 |
| 数据层 | A1 接入调度 · A2 数仓质量 | 常驻 | 数据是产品本身 |
| 后端 | A3 行情内容 · A4 用户权限 · A5 合规 · A6 CRM | 任务型 | 按 bounded context 拆分 |
| 前端 | A7 C端 H5 · A8 中后台四合一 | 任务型 | 中后台共用一套设计系统 |
| 平台 | A9 安全 · A10 设计 · A11 测开 · A12 E2E · A13 SRE | 混合 | 安全与 SRE 常驻 |
| 业务角色 | A14 运营 · A15 管理员 · A16 合规复核 · A17 拓客 · A18 模拟用户 · A19 红队 | 混合 | 前四个是"电子员工"，后两个是验证者 |

**配比：6 人 : 20 agent ≈ 1 : 3.3**
为什么不是 1 : 10 —— 因为这个行业的瓶颈不是"写不出来"，是"谁来担责"。压到 1 : 10，产出会全部堆在评审队列里，评审退化成盖章。

## 2. 运行环路

```
① 需求          H1 → 写 PRD + 验收标准（机器可校验）
                        ↓
② 契约          A0 → 改 OpenAPI/protobuf → 契约 diff → H2 签字
                        ↓
③ 并行实现      A3/A4/A5/A6/A7/A8 各自在 ownership 目录内实现
                A1/A2 补数据面，A10 补设计
                        ↓
④ 机器门禁      lint → 类型 → 单测 → 契约测试 → 数据校验 → 安全扫描
                （A11 拥有门禁一票否决）
                        ↓
⑤ 集成交付      A12 跑 E2E（真栈 + 录播数据）→ 全绿
                        ↓
⑥ 人审          H2 架构级 / H3 合规 / H5 安全与发布
                        ↓
⑦ 灰度发布      A13 执行 1% → 10% → 100%，可一键回滚
                        ↓
⑧ 反馈闭环      A14 看板归因 / A18 用户走查 / A19 红队 / A16 合规抽查
                        ↑__________________________|
```

**关键设计：环路里只有 ③ 是"agent 自由发挥"的环节，其余每一环都有外部约束。** 这是防止 agent 产出失控的唯一可靠结构——不是靠提示词，是靠环路。

## 3. 门禁分级（谁能在什么上签字）

| 变更类型 | 自动门禁 | 人审 | 说明 |
|---|---|---|---|
| 文案 / 样式 / 埋点 | CI 绿 | — | 唯一可以纯自动合入的类别 |
| 业务逻辑 | CI + 契约 diff | — | 契约未变更即可自动 |
| 指标口径 / 数据模型 | CI + golden 回归 | **H4** | 口径错了全盘错 |
| 契约破坏性变更 | CI + diff 声明 | **H2** | 删字段/改类型/改语义 |
| 数据库迁移 | CI + 回滚脚本 | **H2** | 必须可回滚 |
| 认证 / 鉴权 / 密钥 | CI + SAST | **H5 + A9** | agent 只能提案，不能独立合入 |
| 合规规则 / 对外话术 | CI + 规则测试 | **H3** | 红线清单变更须签批 |
| 生产发布 | 全绿 + 灰度演练 | **H5** | agent 执行，人不执行但批准 |
| 权限授予（含 agent 身份） | CI + 双人确认 | **H5** | 敏感权限额外复核 |

**硬约束：agent 永远不能批准 agent。** 任何"agent 审核 agent"的路径只允许存在于门禁的自动化部分（脚本），不允许存在于审批的决策部分。

## 4. 人机同权：agent 是独立主体

H5 要同时支持"agent 调用"和"员工手动配置"，正确做法**不是做两套系统**：

```
        员工 UI (A8)       agent 工具调用 (A14/A15)
                \              /
                 \            /
              ┌──────────────┐
              │ Config Service│  ← 单一 API、单一权限模型、单一审计
              └──────────────┘
                     │
        草稿 → 校验 → 审批 → 发布 → 可回滚
```

四条规则：

1. **独立机器身份**：每个 agent 一个 service account，独立 RBAC，最小权限，可吊销。禁止共享人类账号、禁止共用 token。
2. **同一条流水线**：agent 和人都必须走"草稿→校验→审批→发布"。agent **不能直写生产配置**。
3. **并发控制**：乐观锁 + 配置分片归属（哪个配置项归人、哪个归 agent 要明确），否则 agent 会静默覆盖人的编辑。
4. **可区分来源**：界面上必须能看出"这次是 A14 改的还是张三改的"，以及 agent 侧的模型版本与运行 id。

> 这条不做好一定出事：某个 agent 半夜改错一个栏目配置，全量用户看到错数据，而你没有 diff、没有审批记录、没法回滚。

## 5. 交接协议（handoff contract）

agent 之间交接**不靠对话，靠工件**。每个交接必须包含：

```yaml
handoff:
  from: A3
  to: A12
  artifact: "services/market 的行情聚合接口 v1.2"
  contract_ref: "contracts/openapi/market.yaml#/paths/quote"
  acceptance: ["P95 < 200ms", "契约测试绿", "as_of 字段必现"]
  known_gaps: ["板块聚合暂不支持北交所"]
  rollback: "feature flag market.quote.v2 = off"
```

没有 `acceptance` 的交接视为未完成。**禁止"我写完了，你看着办"式的交接。**

## 6. 审计与留痕（本身是合规要求）

每次 agent 运行必须落一条记录：

| 字段 | 说明 |
|---|---|
| principal | agent id + 版本 |
| model / prompt_version | 哪个模型、哪版提示词 |
| inputs / outputs | 摘要 + 哈希 |
| tool_calls | 调用了什么工具、参数、结果 |
| human_override | 是否被人推翻、推翻理由 |
| decision_basis | 若涉及判断，引用的规则条目 |

`human_override` 这一列是宝贝：**它同时是质量指标和合规证据。** 定期看"哪个 agent 被推翻最多"，就知道该重写谁。

## 7. 成本与容量

| 项 | 控制手段 |
|---|---|
| token | 分级模型（推理型只给 A0/A2/A5/A16/A19）· 任务型 agent 用完即弃，不常驻 |
| tushare 配额 | 回补预算化 · CI 一律录播 · 生产只跑增量 |
| 人类评审 | **限制并行 WIP**（同时最多 3 个 agent 产出在评审队列），评审带宽是真正的天花板 |
| 环境 | IaC + preview 环境按需起停，不常驻 |

**经验值：一个 agent 的边际成本不是它的调用费，是它占用的评审分钟数。** 加 agent 前先算这个。

## 8. Sprint 0 启动顺序（建议）

1. **H2 先定契约规范**（OpenAPI vs protobuf，版本策略）→ 这是所有并行开发的前置。
2. **A0 产出第一版契约**（只做 P0 的：行情、资讯、自选、用户、配置）。
3. **A13 先搭 CI 骨架**（哪怕业务代码还没有）→ 门禁必须先于产出存在。
4. **A1/A2 打通最小数据链路**（日线 + 复权 + 一个质量规则 + golden 样本 20 条）。
5. **A3/A7 做一条竖切片**（个股页：接口 → 页面 → E2E）。
6. **A11/A12 同步补门禁与 E2E**，不等功能做完。
7. 竖切片跑通后再横向铺开。**不要先铺 6 个面的架子。**

## 9. 熔断规则（agent 失控时怎么办）

| 现象 | 处置 |
|---|---|
| 同一 agent 连续 2 次产出被人类推翻 | 暂停该 agent，重写 system_prompt，换上下文重新实例化 |
| 同一模块一周内 3 次返工 | 升级为 H2 亲自主持的架构复盘，暂停并行 |
| 契约冲突 > 2 次/周 | 契约粒度太粗，A0 重新切分 |
| 评审队列 > 5 个待审 | 停止派发新任务，先清队列 |
| 任一 agent 触碰 forbidden 写域 | 立即吊销该身份，全量审计其历史操作 |

**长期常驻的 agent 会累积错误假设。** 开发类 agent 应任务型、用完即弃；只有 A0/A9/A13/A16 值得常驻。
