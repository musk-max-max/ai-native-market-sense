# 金融研究子 agent 席位评估与配置建议

> **文档目的**：评估 market-sense 进入「投资服务场景」阶段时，是否需要在现有 20 个 agent 编制外新增金融研究类专业 agent 席位；若新增，给出角色拆分、接入方式、权限分层、排期与成本风险，产出可直接写入 `agents/roster.yaml` 的字段雏形。
> **评估范围**：编制与架构（roster.yaml / ownership.yaml）、合规红线（H3 红线清单 + P0 验收）、数据面（tushare + 数仓 ADS 层）。
> **确定性标注**：文中对现有编制的引用基于 `agents/roster.yaml`（v0.1.0, updated 2026-11-03）与 `docs/p0-acceptance.md` 实读；tushare 具体接口名标注「⚠️ 待 H4 按商用授权套餐核定」。
> **一个路径更正**：任务简报所引 `/market-sense/agents/roster.yaml` 在当前工作区不存在；实际唯一定义源为**工作区根目录 `agents/roster.yaml`**。本建议以实际文件为准，落地改动也应改该文件。

---

## 0. 结论速览（TL;DR）

| 问题 | 结论 |
|---|---|
| **要不要加？** | **要加。** 现有 A0–A19 无一具备「金融研究/投研分析」专业职能——它们是工程、合规、运营、测试角色。投研分析是**领域知识生产**，不是工程实现，不能靠 A0（架构）、A2（数仓建模）、A3（行情后端）兼任而不破坏单一职责与合规边界。 |
| **加几个？** | **加 3 个**（不是 1 个泛化研究 agent）：A20 投研数据分析师、A21 宏观与政策研究员、A22 投资标的与基金研究员。 |
| **编号** | 沿用 A0–A19 体系，顺延为 **A20 / A21 / A22**，`type: 常驻`（投研观点需持续产出）。 |
| **模型** | 三者**一律 `sensenova-6.8-flash`**（用户硬约束）。 |
| **何时引入** | **P0 不引入**；A20 于 **P1** 引入（先 shadow 只读模式），A21/A22 于 **P2** 引入。 |
| **核心合规约束** | 三者边界一律写死：**不荐股、不给目标价/涨跌预测、输出标注为「信息整合非投资建议」、带 as_of、必过 A16 合规复核 + H3 终审**。 |

## 1. 要不要加：必要性论证

### 1.1 现有 20 个 agent 的职能覆盖盘点

将 A0–A19 按职能归类，可清晰看出**投研分析这一格是空的**：

| 职能族 | 现有席位 | 是否覆盖「金融研究」 |
|---|---|---|
| 架构/契约 | A0 | ❌ 工程治理 |
| 数据工程 | A1 接入调度、A2 数仓建模/质量 | ❌ 管数据"对不对、到没到"，**不产出投研观点** |
| 后端服务 | A3 行情内容、A4 身份权限、A5 合规域、A6 CRM | ❌ 接口实现；A3 甚至被明确禁止"做任何投资判断性文案" |
| 前端 | A7 C 端 H5、A8 中后台 | ❌ 展示层 |
| 平台/安全 | A9 安全、A13 SRE | ❌ |
| 设计 | A10 | ❌ |
| 质量门禁 | A11 契约数据、A12 E2E | ❌ |
| 业务角色 | A14 运营、A15 管理员、A16 合规复核、A17 拓客、A18 模拟用户、A19 红队 | ❌ **无一是投研专业角色** |

**关键判据**：A2（数仓）最接近数据，但它的使命是"保证数据对"，产出的是**指标 SQL / 质量规则 / golden dataset**，不是「龙虎榜游资席位结构化研判」「宏观政策解读」「公募持仓特征分析」。A3（行情后端）的 system_prompt 第 4 条明确写着"不许在接口层做任何投资判断性文案（合规红线）"——**现有体系在制度上就把投研观点挡在门外了**。

### 1.2 为什么不能复用现有 agent 兼任

| 复用方案 | 否决理由 |
|---|---|
| 让 A2 数仓兼任投研 | 职责冲突：A2 是"数据对不对的最终技术判断者"，一旦兼投研，会出现"为了观点好看而放宽质量阈值"的利益冲突，破坏其 gate 的公正性。 |
| 让 A3 行情后端兼任 | 直接违反其既有 system_prompt 红线（接口层不做投资判断文案）。 |
| 让 A16 合规复核兼任 | 荒谬：生产投研观点的一方不能同时是复核方，违反职责分离（separation of duties）。 |
| 让 A17 拓客兼任 | A17 已被禁止提供个股建议，方向相反。 |
| 让 H1/H6 人类兼任 | 投研是高频、专业、可规模化的知识生产，应由 agent 承担，人类做治理签字（H3/H4）。 |

### 1.3 结论

**必须新增。** 且不能只加 1 个泛化"研究 agent"——金融研究内部至少存在**资金面/结构化数据**、**宏观政策**、**标的与基金**三个专业面，知识结构、数据接口、合规敏感度都不同，塞进一个 agent 会导致 prompt 臃肿、上下文互相污染、边界难以界定。故拆为 **3 个**。

## 2. 加什么角色：3 个研究 agent 的专业拆分

三者共同构成一条「**数据 → 结构化研判 → 合规过滤 → C 端呈现**」的投研产出链，各自聚焦一个专业面。

### 2.1 A20 — 投研数据分析师（quant-research）

- **专业面**：资金面 + 结构化数据。龙虎榜/游资席位、两融、北向资金、五档资金流、公募持仓变动的**结构化归因分析**。
- **为什么独立**：纯数据驱动、可量化、合规敏感度相对最低（描述"发生了什么"而非"该买什么"），适合**第一个引入**验证整条投研产出链。
- **输入数据（tushare，⚠️ 接口名待 H4 核定）**：
  - 龙虎榜明细 / 营业部席位 / 席位上榜后 N 日胜率统计
  - 融资融券余额与买入额（沪深京三市）
  - 沪深股通（北向）专用席位成交与净买额
  - 主力/超大单/大单/中单/小单 五档资金流（个股/板块/大盘）
  - 十大流通股东 / 股东户数 / 机构调研
- **输出**：
  - 给前端（C 端 H5）：盘后「资金面复盘」结构化卡片（龙虎榜净买额排行、北向动向、两融变化、板块资金流归因），带 as_of
  - 给其他 agent：向 A21/A22 供给资金面事实底座；向 A16 供给复核所需的"数据依据"
- **边界（红线）**：只做**已发生数据的结构化归因与描述**，不做标的推荐、不给买卖方向、不给目标价、不预测涨跌概率（区别于东财"席位胜率榜"那种概率呈现——可引用公开统计但**不得据此给个体化建议**）。
- **model**：`sensenova-6.8-flash`

### 2.2 A21 — 宏观与政策研究员（macro-policy-research）

- **专业面**：国内外宏观形势、政策解读、跨资产与全球市场联动研判。
- **为什么独立**：输入是**宏观指标 + 政策文本 + 全球行情**，与 A20 的微观资金面数据源完全不同；政策解读涉及**表述合规风险最高**（易被误读为对市场的方向性预测），必须单独设边界。
- **输入数据（tushare + 公开信息，⚠️ 待核定）**：
  - 宏观经济数据：CPI/PPI、货币供应、社融、PMI 等（含指标定义/来源）
  - 全球指数行情条（美/欧/亚主要指数）
  - 利率/汇率/大宗商品（债、期货、外汇）
  - 政策与要闻文本（7×24 快讯、宏观政策资讯）——⚠️ 外部文本需走可信源白名单
- **输出**：
  - 给前端：盘前「宏观与政策早报」、盘中要点、盘后整体研判（国内外形势 + 政策 + 全球联动），带 as_of 与信息来源
  - 给其他 agent：为 A20/A22 提供"宏观背景"上下文；向 H3 提交政策敏感表述的预审
- **边界（红线）**：政策解读**只做事实梳理与公开信息整合**，不得输出"利好/利空某板块该买入"这类**方向性、时机性结论**；对著名投资人/机构持仓的引用**仅作公开信息陈述**，不得推断为操作建议。涉及监管敏感方向立即升级 H3。
- **model**：`sensenova-6.8-flash`

### 2.3 A22 — 投资标的与基金研究员（instrument-fund-research）

- **专业面**：个股基本面特征、公募/私募/ETF 产品特征、基金经理与基金公司维度。
- **为什么独立**：标的与基金涉及**适当性（suitability）敏感区**——一旦滑向"推荐某只基金/股票"即触碰持牌红线，须最严格的输出过滤。
- **输入数据（tushare，⚠️ 待核定）**：
  - 个股基本面：三档 PE、财务报表、行业四分位对比、股东结构
  - 基金：净值/累计净值、分类、基金经理、基金公司、规模、持仓（F10）、多机构评级
  - ETF/LOF 场内数据、新发基金
- **输出**：
  - 给前端：标的"特征画像"（估值分位、基本面四分位定位、股东户数趋势）、基金"产品特征卡"（分类/规模/费率/经理/历史业绩区间），带 as_of
  - 给其他 agent：向 A20 提供标的背景；向 A16 供给适当性相关的复核材料
- **边界（红线）**：**只做特征画像与事实聚合**（"这只基金近三年年化 X%、规模 Y、费率 Z、属于股票型"），**严禁**输出"值得买/推荐/评级/目标价/优先配置"等结论；不做适当性匹配（那是 A4/A5/人工的事）；基金经理业绩**不得表述为未来收益承诺**。
- **model**：`sensenova-6.8-flash`

### 2.4 三者协作与边界关系

```
            ┌──────────────── 数据底座（A1 接入 / A2 数仓 ADS）───────────────┐
            │                                                                  │
   A20 资金面结构化     A21 宏观与政策         A22 标的与基金特征
   (盘后复盘/资金归因)   (盘前/盘中/盘后研判)   (标的/基金画像)
            │                  │                     │
            └────────┬─────────┴──────────┬──────────┘
                     ▼                    ▼
            A16 合规复核（初筛+复核包）──→ H3 合规终审（红线清单/话术白名单）
                     │
                     ▼
            A3 行情/内容后端（内容域投研栏目接口，带 as_of）
                     │
                     ▼
            A7 C 端 H5（AI 生成标识 + 免责常驻 + 分级展示）
```

三者**互不写对方产物**，只通过结构化输出交接；都只读数仓聚合层，都不过 H3 不得对外发布。

## 3. 如何接入现有体系

### 3.1 产出的消费路径

1. **研究 agent 产观点**：A20/A21/A22 读取数仓 ADS 聚合层（经治理的只读查询工具），产出**结构化研判产物**（JSON/Markdown，落 `research/` 各自写域）。
2. **合规过滤**：产物进入 **A16 合规复核**，A16 依据 **H3 红线清单 + 话术白名单**初筛，生成"可签署复核包"，**H3 终审签字**后方可发布。审核链路 **fail-closed**（A5 审核服务不可用即拦截，沿用 A5 既有语义）。
3. **后端供给**：通过的内容经 **A3 行情/内容域**以投研栏目接口对外供给，每条带 `source.as_of`（严格沿用 P0 验收 AC-2 语义：UI 文本与 API `source.as_of` 严格一致）。
4. **C 端呈现**：**A7 H5** 渲染时，凡模型生成内容必须带「**AI 生成**」标识 + **免责声明常驻不可关闭**（沿用 P0 验收 AC-4：免责首屏可见、无任何关闭/折叠入口），并按用户权限层级做**分级展示**。

### 3.2 受哪些既有红线约束

| 既有红线 | 来源 | 对研究 agent 的落点 |
|---|---|---|
| 不做 AI 荐股/评级、目标价 | `docs/p0-acceptance.md`「不做」清单 | 写进三者 `forbidden`，且 A22 尤严 |
| 免责声明首屏常驻、无关闭控件 | P0 AC-4 | A7 渲染层强制，运营不可关 |
| as_of 时间戳严格一致 | P0 AC-2 / A3 硬规则 3 | 研究产物每条必须带 as_of |
| 数据分级与脱敏 | H5 权限模型 / A9 | 研究读取按层级放行，见 §4 |
| agent 永远不能批准 agent | `agents/README.md` §3 / ownership reviewers 仅 H1–H6 | 研究观点**必须** H3 终审，A16 只能出复核包不能终审 |
| 接口层不做投资判断文案 | A3 system_prompt 硬规则 4 | 投研判断文案集中在 `research/` 产物 + 合规过滤后经内容接口分发，A3 仍不做判断 |

### 3.3 编号与登记

- 编号：**A20 / A21 / A22**，顺延现有 A0–A19，无冲突。
- `type`：三者均 `常驻`（投研观点需盘前/盘中/盘后持续产出，非一次性任务）。
- `ownership.yaml`：需在 `reserved_paths` 新增 `research/quant/`(A20)、`research/macro/`(A21)、`research/fund/`(A22)，并在 `paths` 正式登记后由 **A0** 补建目录、reviewer 含 **H3**（因其产出对外表述敏感）。CI path guard 维持 `unmatched_paths: deny` 默认拒绝。

## 4. 权限分层

用户强调"权限要分层"。研究 agent 是**只读数据消费者 + 受审内容生产者**，权限模型如下：

### 4.1 数据读取分层

| 层级 | 内容 | 研究 agent 权限 |
|---|---|---|
| L0 公开行情/宏观 | 指数、个股行情、宏观指标 | ✅ 可读（经数仓 ADS 聚合层） |
| L1 结构化资金/持仓 | 龙虎榜、两融、北向、五档资金流、公募持仓 | ✅ A20/A22 可读（聚合口径） |
| L2 标的基本面/基金档案 | 财报、估值分位、基金 F10 | ✅ A22 可读 |
| L3 用户数据 / PII | 用户身份、自选、CRM 客户、适当性档案 | ❌ **一律禁读** |
| L4 生产库 DDL / 生产环境 | 生产 DB、生产配置 | ❌ **一律禁写/禁操作** |

- 研究 agent **只读 ADS/DWS 聚合层**，经治理的只读查询工具（如 `query_warehouse_ro`），**不直连生产 OLTP**、**不碰用户 PII**（对齐 A9/A18 的"禁止直接访问生产用户数据"语义）。
- 数据分级与脱敏策略由 **H5** 定义、**A9** 落地；研究 agent 无权调整。

### 4.2 写权限与越界

- `write_scope` 仅限各自 `research/` 子目录（产物），**forbidden**：业务代码、契约、数仓 SQL、生产数据库、生产发布、合规规则、用户数据。
- `must_escalate`：任何可能被解读为投资建议的表述、监管敏感方向、数据源不可用>30min、需越出只读数据面、配额/成本异常。

### 4.3 与 H3 / H5 / A16 的关系

| 关系方 | 角色分工 |
|---|---|
| **H3（合规负责人，veto）** | 定义红线清单与话术白名单；**投研产物发布终审签字**；无签字不得对外。研究 agent 是执行者不是立法者（对齐 A5/A16 既有分工）。 |
| **A16（合规复核 agent）** | 对研究产物**初筛+复核**，产出"H3 可签署复核包"；边界案例升级不得自行裁定。 |
| **H5（安全与运维负责人，veto）** | 定义数据分级/脱敏与权限模型；研究 agent 的机器身份最小权限、可吊销、独立审计（对齐 A9 硬规则 3）。 |
| **H4（数据负责人）** | 核定 tushare 接口范围与套餐档位；指标口径变更签字。 |

> **职责分离硬约束**：生产投研观点的 A20/A21/A22，与复核的 A16、终审的 H3 必须是**三个独立主体**，任何一方不得兼任另一方。

## 5. 落地排期

| 阶段 | 引入动作 | 理由 |
|---|---|---|
| **P0** | **不引入**任何研究 agent | P0 验收明确"不做 AI 荐股/评级、目标价"，P0 聚焦数据工具骨架与合规底线。此时引入投研会冲击 P0 范围与红线。 |
| **P1** | 引入 **A20 投研数据分析师**，**先 shadow（只读+内部产出，不对 C 端发布）**，跑通"数据→研判→A16 复核→H3 终审"全链，再灰度对外 | A20 纯数据驱动、合规敏感度最低，最适合先验证投研产出链与合规过滤是否成立。 |
| **P2** | 引入 **A21 宏观与政策研究员**、**A22 标的与基金研究员**，同样 shadow→灰度 | 宏观政策与标的基金合规敏感度更高（方向性表述、适当性），需在 A20 验证合规链后再上；此时中后台/合规域（A5/A8/A16）已就绪承接审核流。 |

每个 agent 上线均走 **shadow → 灰度 → 全量**，灰度比例与发布卡点由 **H5** 批准（对齐 A13 灰度/回滚语义）。

## 6. 成本与风险

### 6.1 成本

| 成本项 | 评估 | 缓解 |
|---|---|---|
| 上下文/token 成本 | +3 个常驻 agent，且投研需读取大体量行情/宏观/基金数据，token 消耗显著高于工程 agent | 用 `sensenova-6.8-flash`（用户指定）本身就是成本友好型；投研读取走**聚合层摘要**而非原始明细；A13 监控 AI 侧 token 成本（沿用其硬规则 4） |
| 维护成本 | 3 套 prompt + 3 个写域 + 3 条合规过滤链路要维护 | 共用同一套"投研产物 schema + 红线过滤模板"，A0 统一契约定义，避免三套各写 |
| 评测/回归成本 | 投研观点质量难自动化评测 | 沿用 A18（模拟用户）+ A16（合规复核）+ 人工抽检；产出带结构化字段便于回归 |

### 6.2 投研 agent 特有合规风险（最高优先级）

| 风险 | 说明 | 缓解（硬措施） |
|---|---|---|
| **输出被误当投资建议** | 即便标注"信息整合"，用户仍可能把"资金面研判""基金特征"当作买卖依据 | ① 三者 `forbidden` 写死不荐股/不给目标价/不给涨跌预测；② 每条产物强制「AI 生成 + 信息整合非投资建议」标识 + **免责常驻不可关**（A7 强制）；③ A16 初筛 + **H3 终审** fail-closed；④ 话术走白名单 |
| **滑向持牌业务** | 方向性/时机性表述、适当性匹配、收益承诺可能构成无牌投顾 | 红线清单由 H3 定义并动态维护；A22 禁做适当性匹配；A21 禁方向性/时机性结论；A17 既有"客户要投资建议即转人工"语义同样约束研究侧 |
| **政策敏感表述** | 宏观/政策解读易触碰监管红线 | A21 疑似监管敏感内容**立即升级 H3**，不自行判断（对齐 A5 硬规则 5） |
| **引用著名投资人持仓被当操作信号** | "某知名投资人增持 X"易被解读为荐股 | 仅作**公开信息陈述**，明确标注"公开持仓披露，非操作建议"，且不给任何跟进结论 |
| **数据错误传导** | 投研观点建立在数据上，数据错则观点错 | 只读已过 A2 质量门禁的 ADS 层；产物带 `source/as_of/adj_type`（对齐 DA-4）；质量分低于阈值下游阻断 |
| **提示词注入诱导荐股** | A19 已把"让 agent 输出荐股"列为高优攻击面 | 研究 agent 是新攻击面，须纳入 A19 对抗用例；输出过滤不依赖 prompt，**硬编码进工具层**（对齐 roster meta 注：permissions 与 must_escalate 必须硬编码进工具层，不能只写在 prompt 里） |
